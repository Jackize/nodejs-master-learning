Kafka → Nest — ôn nhanh

Bài 14–18: recall Module 2 · topic/group CLI · Nest producer · hybrid consumer · idempotent handler.

Kafka primitives (15)

  • Topic append-only log — ShopStream: shopstream.order.paid (3 partitions)
  • Key → cùng partition → thứ tự theo entity (orderId)
  • Consumer group: cùng group = chia partition; khác group = fan-out
  • Offset = progress group trên partition (at-least-once nếu crash trước commit)

Nest producer (16)

  • Packages: @nestjs/microservices + kafkajs (khớp version Nest)
  • ClientsModule + producerOnlyMode: true
  • emit(topic, { key, value }) + lastValueFrom; connect() trong onModuleInit
  • Emit sau Mongo commit; chỉ khi transition → paid (không spam already-paid)
  • Dual-write: DB paid rồi Kafka fail → mất event (outbox sau)

Nest consumer / hybrid (17)

  • connectMicroservice(Transport.KAFKA) → startAllMicroservices() → listen()
  • @EventPattern('shopstream.order.paid') — @Payload() = value object
  • Nest gắn suffix: group shopstream-notify-v1-server
  • Debug: log + GET /notify/recent

Idempotent consumer (18)

  • Unique (consumer, orderId) trên processed_events
  • Claim-first: insert → notify; E11000 → SKIP
  • Trade-off: crash giữa claim & notify có thể mất 1 lần gửi
  • Giống tinh thần HTTP Idempotency-Key (Bài 12), key = orderId

CLI nhanh

bash 
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --describe --topic shopstream.order.paid

docker compose exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --describe --group shopstream-notify-v1-server

Phỏng vấn nhanh

  • emit vs send — event vs request-reply
  • Hybrid cùng process vs tách worker — ops vs scale độc lập
  • at-least-once + idempotent handler vs “exactly-once” marketing
  • Dual-write vs transactional outbox
