Nest Kafka producer — emit order.paid

Win: khi webhook chuyển order sang paid (lần đầu), Nest emit event lên topic shopstream.order.paid; CLI consumer thấy message có key = orderId. Consumer Nest / @EventPattern → bài sau.

⏱ ~90–120 phút · 🎯 Tự code · đã verify Nest @nestjs/microservices@11.2.3 + kafkajs@2.2.4 trên broker Docker Bài 15 · docs: Nest Kafka.

✍️ Tự làm

Không pre-fill vào shopstream/. Bạn cài package, thêm env, đăng ký ClientsModule, emit sau transaction Mongo commit — chỉ khi status vừa đổi sang paid. Logic HMAC / paid / failed giữ nguyên Bài 11–13.

🌉 Bắc cầu

Bài 15: topic + produce CLI. Bài này: domain (webhook paid) ghi cùng topic qua Nest ClientKafka.emit. Bạn đã biết partition/key — giờ key = orderId để notify/analytics sau này giữ thứ tự theo order.

💡 emit vs send (1 phút)

emit = event-based: fire-and-forget (có ack broker), không chờ reply topic.
send = request-response: Nest tạo reply topic + correlation id — thừa cho “order đã paid, ai quan tâm thì nghe”.
ShopStream notify → dùng emit. Docs Nest: Event-based / Publishing events.

⚠️ Dual-write (nói thẳng — sẽ đào sâu outbox sau)

Pattern bài này: Mongo commit rồi mới Kafka. Nếu emit lỗi sau khi DB đã paid → order paid nhưng không có event (mất notify). Ngược lại, emit trong transaction Mongo cũng không “atomic” với Kafka. Production hay dùng outbox — Sprint B. Bài này chấp nhận dual-write có ý thức + emit chỉ khi transition (không spam khi webhook retry trên order đã paid).

4. Đăng ký ClientsModule (producer-only)

producerOnlyMode: true = Nest không join consumer group chỉ để publish — đúng cho API HTTP chỉ emit. Docs Nest Kafka → Options → producerOnlyMode.

src/orders/orders.module.ts — imports thêm 
import { Module } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { ClientsModule, Transport } from '@nestjs/microservices';
import { MongooseModule } from '@nestjs/mongoose';
import { KAFKA_PRODUCER } from '../messaging/kafka.constants';
// ... các import cũ (Cart, Catalog, Auth, schemas, controllers)

@Module({
  imports: [
    MongooseModule.forFeature([
      /* Order + IdempotencyRecord như cũ */
    ]),
    AuthModule,
    CartModule,
    CatalogModule,
    ClientsModule.registerAsync([
      {
        name: KAFKA_PRODUCER,
        inject: [ConfigService],
        useFactory: (config: ConfigService) => ({
          transport: Transport.KAFKA,
          options: {
            client: {
              clientId: 'shopstream-api',
              brokers: config
                .getOrThrow<string>('KAFKA_BROKERS')
                .split(',')
                .map((b) => b.trim())
                .filter(Boolean),
            },
            // Chỉ producer — không đăng ký consumer group thừa
            producerOnlyMode: true,
          },
        }),
      },
    ]),
  ],
  controllers: [OrdersController, WebhooksController],
  providers: [OrdersService],
  exports: [OrdersService],
})
export class OrdersModule {}

5. OrdersService — connect + emit sau transition

Ba điểm bắt buộc:

  1. await this.kafka.connect() trong onModuleInit.
  2. Cờ becamePaid = true chỉ khi đổi từ pending_payment → paid trong transaction (không emit khi order đã paid — webhook retry).
  3. Emit sau withTransaction thành công; dùng lastValueFrom(this.kafka.emit(...)) để chờ broker ack. Payload dạng { key, value } (Nest docs — keyed messages).
src/orders/orders.service.ts — imports + constructor (bổ sung) 
import { Inject, Injectable, OnModuleInit, /* ...exceptions cũ */ } from '@nestjs/common';
import { ClientKafka } from '@nestjs/microservices';
import { lastValueFrom } from 'rxjs';
import { KAFKA_PRODUCER, ORDER_PAID_TOPIC } from '../messaging/kafka.constants';

@Injectable()
export class OrdersService implements OnModuleInit {
  constructor(
    /* ... inject cũ: orderModel, cart, product, connection, config, idempotency... */
    @Inject(KAFKA_PRODUCER) private readonly kafka: ClientKafka,
  ) {}

  async onModuleInit(): Promise<void> {
    await this.kafka.connect();
  }

  // ... checkout / helpers giữ nguyên
}
handlePaymentWebhook — phần paid (ý chính) 
async handlePaymentWebhook(...): Promise<OrderResponse> {
  // 1) verify HMAC như Bài 13 — giữ nguyên
  const session = await this.connection.startSession();
  try {
    let orderDoc!: OrderDocument;
    let becamePaid = false; // chỉ true khi transition lần đầu

    await session.withTransaction(async () => {
      const order = await this.orderModel.findById(dto.orderId).session(session).exec();
      if (!order) throw new NotFoundException('Order not found');

      if (dto.result === 'paid') {
        if (order.status === OrderStatus.Paid) {
          orderDoc = order;
          return; // already paid → không emit lại
        }
        if (order.status !== OrderStatus.PendingPayment) {
          throw new ConflictException(`Cannot mark paid from status ${order.status}`);
        }
        order.status = OrderStatus.Paid;
        await order.save({ session });
        orderDoc = order;
        becamePaid = true;
        return;
      }

      // failed → cancel + releaseStock — giữ nguyên Bài 11; KHÔNG emit order.paid
      // ...
    });

    // 2) Sau khi Mongo commit — mới publish
    if (becamePaid) {
      await this.publishOrderPaid(orderDoc);
    }

    return this.toResponse(orderDoc);
  } finally {
    await session.endSession();
  }
}

private async publishOrderPaid(order: OrderDocument): Promise<void> {
  const orderId = order._id.toString();
  await lastValueFrom(
    this.kafka.emit(ORDER_PAID_TOPIC, {
      key: orderId, // cùng order → cùng partition
      value: {
        orderId,
        userId: order.userId.toString(),
        total: order.total,
        status: OrderStatus.Paid,
        paidAt: new Date().toISOString(),
      },
    }),
  );
}
Nếu emit throw sau khi DB đã paid?

Webhook trả 5xx → provider có thể retry. Lần 2: order đã paid → becamePaid=false → không emit lại → event vẫn mất. Đó đúng là lỗ hổng dual-write. Ghi nhớ cho outbox / replay tooling sau — đừng “sửa” bằng emit mọi lần already-paid (sẽ spam consumer).
