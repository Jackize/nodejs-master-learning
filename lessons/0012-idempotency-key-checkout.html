Idempotency key HTTP (checkout)

Win: POST …/checkout bắt buộc header Idempotency-Key; gọi lại cùng key → cùng một order, stock chỉ trừ một lần (không double-checkout khi client retry).

⏱ ~75–100 phút · 🎯 Tự code — pattern giống Stripe Idempotent requests.

✍️ Tự làm

Không pre-fill vào shopstream/. Giữ route checkout hiện tại (/order/checkout hoặc /orders/…). Webhook Bài 11 không đổi.

🌉 Bắc cầu

Checkout đã atomic trong transaction — nhưng hai request HTTP (timeout → client bấm lại) vẫn tạo hai order / trừ stock hai lần. Idempotency-Key = client gửi UUID; server nhớ kết quả lần đầu. Đây là nền tư duy trước Kafka consumer (at-least-once → xử lý trùng).

💡 Vì sao bắt buộc key trên checkout?

Stripe cho phép không gửi key (mỗi lần = thao tác mới). ShopStream require key ở checkout để bạn không quên — money/path nguy hiểm. Key scope theo userId (user A không tái sử dụng record của user B).

1. Schema lưu key

# tạo file trong editor: src/orders/schemas/idempotency-record.schema.ts
idempotency-record.schema.ts — ý chính 
export enum IdempotencyStatus {
  Started = 'started',
  Completed = 'completed',
}

@Schema({ timestamps: true, collection: 'idempotency_records' })
export class IdempotencyRecord {
  @Prop({ type: Types.ObjectId, ref: 'User', required: true })
  userId!: Types.ObjectId;

  @Prop({ required: true, trim: true, maxlength: 255 })
  key!: string;

  @Prop({ required: true, enum: Object.values(IdempotencyStatus) })
  status!: IdempotencyStatus;

  @Prop({ type: Types.ObjectId, ref: 'Order', default: null })
  orderId?: Types.ObjectId | null;
}

// Unique compound — claim key atomic qua insert
IdempotencyRecordSchema.index({ userId: 1, key: 1 }, { unique: true });

  @Headers('idempotency-key') idempotencyKey: string | undefined,

Nest/Express normalize header về chữ thường → dùng 'idempotency-key'. Client gửi Idempotency-Key (chuẩn Stripe).

3. Service — claim → checkout → complete

orders.service — luồng 
async checkout(userId: string, idempotencyKey?: string) {
  if (!idempotencyKey?.trim()) {
    throw new BadRequestException('Idempotency-Key header is required');
  }
  const key = idempotencyKey.trim();
  const uid = new Types.ObjectId(userId);

  try {
    await this.idemModel.create({
      userId: uid, key, status: IdempotencyStatus.Started, orderId: null,
    });
  } catch (err: unknown) {
    if ((err as { code?: number }).code !== 11000) throw err;
    const existing = await this.idemModel.findOne({ userId: uid, key }).exec();
    if (existing?.status === IdempotencyStatus.Completed && existing.orderId) {
      const order = await this.orderModel.findById(existing.orderId).exec();
      if (!order) throw new NotFoundException('Order not found');
      return this.toResponse(order); // replay — không holdStock lại
    }
    throw new ConflictException('Idempotency key in progress');
  }

  try {
    const order = await this.createOrderFromCart(userId); // logic Bài 10
    await this.idemModel.updateOne(
      { userId: uid, key },
      { $set: { status: IdempotencyStatus.Completed, orderId: new Types.ObjectId(order.id) } },
    ).exec();
    return order;
  } catch (err) {
    await this.idemModel.deleteOne({ userId: uid, key }).exec(); // cho retry cùng key khi fail
    throw err;
  }
}

Tách createOrderFromCart (transaction hold + create + clear) khỏi lớp idem — dễ test.

Góc phỏng vấn

Q: Idempotency HTTP vs idempotent Kafka consumer?
A gọn: Cùng ý “xử lý trùng an toàn”. HTTP: client gửi key, server lưu response. Consumer: thường dedupe theo eventId / business key đã xử lý. Module 3 sẽ gặp bản event-driven.
