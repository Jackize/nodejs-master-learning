Cấu trúc Nest + config 12-factor

Win: thiếu MONGODB_URI thì app không start; có đủ env thì /health vẫn xanh — Health tách thành module riêng.

⏱ ~40–50 phút · 🎯 Mục tiêu: fail-fast config + module boundary trước khi viết Catalog.

🌉 Bắc cầu từ Bài 00

Bạn đã có Nest nối Mongo qua ConfigModule + default URI trong code. Default “tiện” local nhưng nguy hiểm production: deploy quên set env → app lặng lẽ trỏ localhost và chết khó hiểu. Bài này siết đúng một việc: validate env lúc bootstrap + tách HealthModule khỏi “god” AppModule.

💡 Vì sao làm trước Catalog?

Product company kỳ vọng app chết sớm (fail fast) khi config sai — không phải 500 lúc request đầu tiên. Theo Twelve-Factor: Config, config nằm trong môi trường. Nest hỗ trợ schema Joi qua ConfigModule.forRoot({ validationSchema }) — xem Nest Configuration — Schema validation.

1. Module boundary: Health không nằm trong AppModule

CRUD freelance hay nhét mọi controller vào AppModule. Khi có catalog/cart/order, file đó thành bãi rác. Pattern Nest: mỗi feature một module, AppModule chỉ ghép.

2. Schema env — bắt buộc MONGODB_URI

required() khiến Nest ném Config validation error ngay khi bootstrap nếu thiếu biến. PORT / NODE_ENV có default hợp lý; URI thì không default ngầm trong schema (tránh deploy nhầm).

src/config/env.validation.ts (file mới — cần mkdir -p src/config) 
import * as Joi from 'joi';

// Validate process.env lúc bootstrap — fail fast
export const envValidationSchema = Joi.object({
  NODE_ENV: Joi.string()
    .valid('development', 'production', 'test')
    .default('development'),
  PORT: Joi.number().port().default(3000),
  // Bắt buộc: không soft-default URI production → localhost
  MONGODB_URI: Joi.string().min(1).required(),
});
bash — tạo thư mục config 
mkdir -p src/config

3. Ghép vào AppModule + main đọc PORT từ ConfigService

src/app.module.ts 
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { MongooseModule } from '@nestjs/mongoose';
import { AppController } from './app.controller';
import { AppService } from './app.service';
import { envValidationSchema } from './config/env.validation';
import { HealthModule } from './health/health.module';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      validationSchema: envValidationSchema,
      validationOptions: { abortEarly: false }, // báo đủ lỗi một lần
    }),
    MongooseModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        // getOrThrow: TypeScript + runtime đều không cho undefined
        uri: config.getOrThrow<string>('MONGODB_URI'),
      }),
    }),
    HealthModule,
  ],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
src/main.ts 
import { NestFactory } from '@nestjs/core';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const config = app.get(ConfigService);
  const port = config.get<number>('PORT', 3000);
  await app.listen(port);
  console.log(`ShopStream API đang lắng nghe http://localhost:${port}`);
}
bootstrap();
.env.example 
# Bắt buộc — app không start nếu thiếu

PORT=3000
NODE_ENV=development

Góc phỏng vấn

Q: “Config trong code vs env — chọn thế nào?”
A gọn: Secret/URI/feature flag theo môi trường → env (12-factor). Default an toàn cho local OK với biến không nhạy cảm (PORT); biến quyết định “nói chuyện với hệ thống nào” (MONGODB_URI) nên required, không default ngầm production.
