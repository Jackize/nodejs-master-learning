Học Kafka “chay” (không broker) hoặc Nest không Mongo sẽ tạo ảo giác hiểu. Product company kỳ vọng bạn chạy được stack. Deadline phỏng vấn cuối tháng 8 → càng không được mất thời gian cài đặt giữa chừng.

3. Bước 1 — Bật Mongo + Kafka

Vì sao Compose? Một lệnh nâng cả hai dependency; cùng network Docker; tái lập được trên máy khác (portfolio / laptop phỏng vấn).

bash — từ root workspace 
# Vào thư mục dự án
cd shopstream

# Kéo image (lần đầu có thể vài phút) và chạy nền
docker compose up -d

# Xem trạng thái — mongo + kafka phải Up
docker compose ps
Kafka KRaft, không ZooKeeper

Kafka hiện đại chạy KRaft (broker + controller trong một process). Image apache/kafka:4.3.1 mặc định phù hợp local. Đừng copy compose cũ còn ZooKeeper từ blog 2020 — dễ lệch với docs hiện tại.

4. Bước 2 — Sanity Mongo & Kafka (không qua Nest)

bash 
# Ping Mongo trong container (ok: 1)
docker compose exec mongo mongosh --quiet --eval "db.adminCommand('ping')"

# Tạo topic smoke-test (chứng minh broker nhận lệnh)
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create --topic shopstream.health --if-not-exists

docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list

Bạn phải thấy topic shopstream.health. Đây là bằng chứng Kafka sống — Nest chưa consume gì cả (cố ý).

5. Bước 3 — Chạy Nest API + /health

Nest nối Mongo qua MongooseModule + URI trong .env (pattern 12-factor: config ngoài code). Theo NestJS MongoDB docs.

bash 
cd api
# Copy env mẫu nếu chưa có .env
cp -n .env.example .env
npm install
npm run start:dev
src/health/health.controller.ts (đã có sẵn) 
@Controller('health')
export class HealthController {
  constructor(@InjectConnection() private readonly connection: Connection) {}

  @Get()
  async check() {
    // readyState === 1 → đã connected
    const mongoOk = this.connection.readyState === 1;
    return { ok: mongoOk, mongo: mongoOk ? 'up' : 'down', service: 'shopstream-api' };
  }
}
bash — terminal khác 
curl -s http://localhost:3000/health
# Kỳ vọng: {"ok":true,"mongo":"up","service":"shopstream-api"}

# Unit test mặc định Nest vẫn xanh
cd shopstream/api && npm test
Port đã bị chiếm?

Nếu 27017/9092/3000 conflict: docker compose ps + lsof -i :3000. Có thể đang còn container từ lần verify trước — docker compose -f shopstream/docker-compose.yml down rồi up -d lại trong shopstream/.

Q: “Vì sao health check phải ping dependency, không chỉ trả 200?”
A gọn: Load balancer/k8s cần biết app sẵn sàng phục vụ. Process Nest sống mà Mongo down → request sẽ 500; health phải phản ánh dependency tới hạn (liveness vs readiness — sẽ sâu hơn Sprint B).
